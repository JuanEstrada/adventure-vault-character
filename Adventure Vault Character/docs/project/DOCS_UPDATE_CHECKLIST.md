# Docs Update Checklist

Usa esta lista cuando termines una sesion o cuando cambie el estado real del
repositorio.

## Revisar Si Hace Falta Actualizar

- `docs/project/SESSION_RESUME.md`
- `docs/project/PROJECT_SNAPSHOT.md`
- `README.md`
- `docs/README.md`
- `docs/project/README.md`
- algun archivo en `docs/specs/`
- algun archivo en `docs/architecture/`
- algun archivo en `docs/adr/`

## Actualiza la Documentacion Si Cambio Algo Real

- flujo implementado
- estado actual del repo
- siguiente paso recomendado
- decisiones nuevas
- archivos o modulos ya creados
- trabajo pendiente que ya no aplica

## No Actualices Por Inercia

- No reescribas documentos solo para cambiar estilo.
- No dupliques informacion si ya existe una fuente de verdad.
- No cambies specs de producto si no hubo una decision real.

## Minimo Esperado

Si cambia el estado del proyecto, actualiza primero:

1. `docs/project/SESSION_RESUME.md`
2. `docs/project/PROJECT_SNAPSHOT.md`

Despues actualiza cualquier documento mas profundo que haya quedado
desalineado.
